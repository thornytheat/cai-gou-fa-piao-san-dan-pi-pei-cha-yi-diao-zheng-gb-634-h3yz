# 数据字典 invoice3way

## 1 单据与匹配键

| 单据 | 文件 | 主键 | 匹配键 |
|---|---|---|---|
| 采购订单 PO | `orders_dirty.csv` / `orders_clean.csv` | 采购单号 + 行号 | `(po_no, line_no)` |
| 入库单 GRN | `receipts_gb18030.csv` | 入库单号 | `(po_no, line_no)` |
| 发票 INV | `invoices_dirty.csv` | 发票号 + 采购单号 + 行号 | `(po_no, line_no)` |
| 供应商主数据 | `supplier_master.csv` | 采购单号 | — |
| 红字发票清单 | `credit_notes.csv` | 红字单号 | 原发票号（配对用） |

匹配键全部按字符串比对：`01` 与 `1` 是两个不同行号，去前导零会让两行错并成一行。

## 2 列定义

### 2.1 采购订单 `po`

| 列 | 标签 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `po_no` | 采购单号 | text | 是 | 字符串保形，不做数值化 |
| `line_no` | 行号 | text | 是 | 两位字符串，保留前导零 |
| `item_code` | 物料编码 | text | 否 | — |
| `item_name` | 物料名称 | text | 否 | 中文，可能含全角字符 |
| `qty` | 订单数量 | qty | 是 | 4 位小数，> 0 |
| `unit_price` | 不含税单价 | amount | 是 | 按 `amount_unit` 折算成元，2 位小数 |
| `amount_unit` | 金额单位 | unit | 是 | 元 / 千元 / 万元；缺省按元 |
| `tax_rate` | 税率 | rate | 是 | `13%`、`0.13`、`13` 三种写法都归一到 0.13 |

### 2.2 入库单 `grn`

| 列 | 标签 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `grn_no` | 入库单号 | text | 是 | — |
| `po_no` / `line_no` | 采购单号 / 行号 | text | 是 | 与采购订单同键 |
| `qty_received` | 实收数量 | qty | 是 | 4 位小数，> 0；超过订单数量 5% 只提示 |
| `received_at` | 入库日期 | date | 是 | 归一成 `YYYY-MM-DD` |
| `warehouse` | 仓库 | text | 否 | 可能含换行（引号内换行算一条记录） |

### 2.3 发票 `inv`

| 列 | 标签 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `invoice_no` | 发票号 | text | 是 | 字符串保形；科学计数法报 `E_KEY_SCIENTIFIC` |
| `invoice_date` | 开票日期 | date | 是 | 归一成 `YYYY-MM-DD` |
| `po_no` / `line_no` | 采购单号 / 行号 | text | 是 | 与采购订单同键 |
| `qty` | 开票数量 | qty | 是 | 4 位小数 |
| `amount_ex_tax` | 不含税金额 | amount | 是 | 折算成元，2 位小数 |
| `tax_rate` | 税率 | rate | 是 | 与订单税率比对用 |
| `amount_inc_tax` | 价税合计 | amount | 是 | 声明值，用于税额差比对 |
| `amount_unit` | 金额单位 | unit | 是 | 元 / 千元 / 万元 |

### 2.4 供应商主数据 `supplier_master`

| 列 | 标签 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `supplier_code` | 供应商编码 | text | 是 | 全角转半角、去空白、转大写后当主键的一半 |
| `supplier_name` | 供应商名称 | text | 是 | 同一编码多个名称时取名称排序第一个当代表名 |
| `po_no` | 采购单号 | text | 是 | 与三单同一个键，按字符串保形；一行一个采购单 |
| `status` | 状态 | text | 否 | 正常 / 停用；缺省按正常 |

采购单号在主数据里查不到时归到「未登记」，不并入相邻供应商；同一采购单登记多次时按编码、名称排序取第一条，并记 `E_MASTER_DUP`。

### 2.5 红字发票清单 `credit_notes`

| 列 | 标签 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `credit_no` | 红字单号 | text | 是 | 字符串保形 |
| `original_no` | 原发票号 | text | 否 | 归一（全角转半角、去空白、转大写）后与发票表配对 |
| `issue_date` | 开票日期 | date | 否 | 归一成 `YYYY-MM-DD` |
| `po_no` | 采购单号 | text | 否 | 为空时该行归「未登记」 |
| `qty` | 数量 | qty | 否 | 4 位小数 |
| `amount_ex` | 不含税金额 | amount | 否 | 见下方负数写法 |
| `tax_rate` | 税率 | rate | 否 | 只做展示与重算，不参与配对 |
| `amount_inc` | 价税合计 | amount | 是 | 冲减以它为准；必须为负 |
| `amount_unit` | 金额单位 | unit | 否 | 元 / 千元 / 万元；缺省按元 |

红字金额的四种负数写法都要认：括号 `(250.00)`、全角负号 `－76.00`、千分位 `-3,487.46`、
单位后缀 `-0.678万元`（= -6780.00 元）。写成正数、写成占位符、解析不出来的行一律拒绝，
记 `E_RED_NOT_NEGATIVE` / `E_RED_SENTINEL` / `E_RED_UNPARSABLE`，不进冲减。

## 3 数值与精度

| 项 | 定义 |
|---|---|
| 金额 | `Decimal`，单位元，量化 `0.01`，`ROUND_HALF_UP` |
| 数量 | `Decimal`，量化 `0.0001` |
| 税率 | `Decimal`，量化 `0.000001`，取值区间 (0, 0.5] |
| 金额容差 | `0.02` 元，`|差| ≤ 0.02` 视为一致 |
| 数量容差 | `0`，数量必须完全相等 |
| 合计 | 只在最后一步量化，中间过程保留原始精度；禁止 float 累加 |
| 对外序列化 | 金额、数量、税率一律字符串（`"1234.50"`），不进 JSON 浮点 |

## 4 空值与空态

- `None`（哨兵）：`-`、`--`、`—`、`/`、`N/A`、`null`、`未知`、`无`、`暂无`、`待定`、`不适用`、`未开票`、空串。哨兵清单只在 `app/config.py` 的 `SENTINELS` 定义一次。
- `0`：真实数值 0，参与合计；与哨兵严格分开。单价为 0 不隔离，金额为负才隔离（`E_NEGATIVE_AMOUNT`）。
- 三种空态必须分开：0 字节 → `E_EMPTY_FILE`（文件级）；只有表头 → `E_HEADER_ONLY`（文件级）；全空行 → 计入 `blank`，不进隔离也不进采纳。
- 重复表头 → 计入 `header_repeat`，按分段导出处理，不产生数据行。

## 4.1 红字冲抵与供应商净额

- 冲减键：归一后的原发票号。找不到原发票 → 「未冲抵」，挂待确认，不进净额（`E_RED_UNMATCHED`）。
- 冲抵状态：红字绝对值 = 原发票价税合计 → 全额冲抵；小于 → 部分冲红（剩余可冲 = 原发票 + 红字）；大于 → 超额冲抵（`E_RED_OVER`，剩余可冲为负）。
- 供应商净额 = 该供应商发票价税合计 + 已冲抵红字；未冲抵红字不进净额，单列「待确认」。
- 守恒：Σ 供应商净额 = 本批发票价税合计 + 已冲抵红字，差额非 0 在页面显式写出来。

## 4.2 入库数量与分批

- 实收 = 同一 `(po_no, line_no)` 下所有入库行数量之和；一行一批时就是一个值，多批时逐批列出。
- 未入库 = 订单数量 − 实收；可以为负，负值表示超收（超过订单数量 5% 判超收）。
- 采购订单行被隔离或缺失时，对应的入库行记「无订单」，不算到任何采购行的实收里。

## 5 去重键与冲突

- 行级去重键：`(单据类型, 文件, 物理行号)`，即 `row_ref`，如 `invoices_dirty.csv:L14`。
- 业务键：发票号。同一发票号出现多行时：
  - 价税合计完全一致 → 保留首行（按 `po_no, line_no, row_ref` 定序），其余记 `E_DUP_KEY_SAME`（记录级，不进隔离）。
  - 价税合计不同 → 全部隔离，记 `E_DUP_KEY_CONFLICT`，两条原值都留在隔离区，由人工裁定。
- 选价税合计而不是不含税金额做冲突判定：价税合计是票面最终金额，财务按它记账。

## 6 区间与包含

- 数量容差与金额容差都是闭区间：`|差| ≤ 容差` 视为一致，`>` 才判差异。
- 超收比例按 `实收 > 订单数量 × 1.05` 判定，边界值 84（订单 80）不算超收，86 算。
- 日期不涉及时区换算：入库日期与开票日期都是纯日期，按 `YYYY-MM-DD` 存储与展示。

## 6.1 重复报销与税率变更

- 重复只比「不同输入摘要」的批次：同一份输入换规则版本重跑不算再次报销。
- 同号不同额 / 同号同额 / 同额不同号三类都报，每条带批次号、发票号、价税合计与证据行。
- 同一批次内的同号不同额由 M3 判 `E_DUP_KEY_CONFLICT` 并整行隔离，复核台账不再重复报。
- 发票税率 ≠ 采购单税率时按发票税率重算应付价税合计；用采购单税率推出来的差额记「迁移额」，不算差错。

## 7 结论枚举

| 结论 | 含义 |
|---|---|
| `matched` | 三单齐全，量差 / 价差 / 税额差全部在容差内 |
| `diff` | 三单齐全，至少一类差异超出容差 |
| `missing` | 三单缺至少一张；细分 `missing_po` / `missing_grn` / `missing_inv` |

差异类别优先级（数字越小越优先）：`conflict` 0、`missing_po` 1、`missing_grn` 2、`missing_inv` 3、`tax` 4、`price` 5、`qty` 6。一行命中多类时，`diff_kind` 取优先级最高的一类，`reasons` 保留全部命中。

## 8 原因码

原因码只在 `app/reasons.py` 定义，含级别（error / warn / info）、所属阶段、结论与复核动作。隔离区、导出 CSV、测试断言都从这里取，不允许在模块里写裸字符串级别。

## 9 运行清单字段

| 字段 | 含义 |
|---|---|
| `run_id` | 一次运行的可读编号，前缀 `3WM-` |
| `batch_id` | 批次号，`B` + UTC 时间戳 + 4 位随机后缀 |
| `batch_key` | `sha256(输入摘要 + 评估日)`，与文件顺序无关 |
| `input_digest` | 各文件 `sha256` 排序后拼接再取 `sha256`；重算用留存原件重算一遍核对 |
| `inputs[].sha256` | 单个输入文件字节摘要，用于复算 |
| `inputs[].source_path` | 采信时的来源路径（只作追溯，重算不读它） |
| `eval_date` | 批次锁定的评估日；重算沿用原值，不随运行参数漂移 |
| `replayed` | 本次运行是否按留存原件重放（重算/重试/中断恢复） |
| `elapsed_ms` | 本次运行耗时，毫秒 |
