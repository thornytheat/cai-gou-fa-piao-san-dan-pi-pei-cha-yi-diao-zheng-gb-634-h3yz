# invoice3way 采购发票三单匹配与差异调整

财务共享中心每月把采购订单、入库单、发票三份导出表贴进同一个工作表逐行对数。
本项目把这一步换成：导入三份脏 CSV → 金额税率归一 → 质量隔离 → 三单匹配 →
差异归因 → 调整单（最大余额法分摊尾差）→ 导出，再在复核台账里看跨批次重复报销、
红字冲减与供应商汇总。

- 客户场景：联纬汽车零部件 · 财务共享中心 9 人，月均 1200 张发票
- 技术形态：FastAPI + SQLite + Jinja2 + 原生 HTML/CSS/JS，单体服务，端口 18203
- 视觉：L2 对账工作台（左右分栏对照 + 中间差异标记 + 顶部固定合计条）

## 能力

| 能力 | 说明 |
|---|---|
| 脏文件采信 | 编码回退（utf-8 → gb18030）、BOM 剥离、分隔符识别、重复表头分段、末行截断识别 |
| 金额税率归一 | 千分位、全角数字、元/千元/万元、税率 `13%` / `0.13` / `13` 三种写法 |
| 质量隔离 | 38 个原因码集中定义，隔离行带原因码 + 行号 + 字段 + 原值，可导出 CSV |
| 三单匹配 | 按 `(采购单号, 行号)` 分组，命中规则全收集后按固定优先级取结论 |
| 差异归因 | 量差 / 价差 / 税额差三类金额 + 缺单（缺哪一张写清楚） |
| 四账核对 | 行账 / 单账 / 金额账 / 隔离账，任一不平显式标出 |
| 调整单 | 按采购单的发票不含税金额加权，最大余额法分摊到分，合计守恒 |
| 幂等与陈旧 | 同输入重跑返回同一批次；旧版本提交 409 拒绝 |
| 重复报销 | 跨批次按同号不同额 / 同号同额 / 同额不同号三类报，同输入重跑不算重复 |
| 红字冲减 | 红字清单单独读取，括号负数、全角负号、万元都能认；未冲抵挂待确认不进净额 |
| 供应商汇总 | 采购单按主数据归到供应商，汇总三方数量、发票含税、红冲、差异与调整额 |
| 分批入库 | 一个采购行多批入库按批相加；采购单行缺失的入库记「无订单」 |

## 模块

| 模块 | 动作 | 入口 |
|---|---|---|
| M1 单据接入 | 导入样例并给出逐行诊断 | `POST /api/import`、页面 `/` |
| M2 金额税率 | 列契约与单格试算 | `GET /api/contract`、`GET /api/contract/preview` |
| M3 质量隔离 | 原因码分布与隔离导出 | `GET /api/quarantine`、`GET /api/quarantine/export.csv` |
| M4 三单匹配 | 三单对照、差异明细、四账 | `GET /api/trios`、`/api/matches`、`/api/diffs`、`/api/reconcile` |
| M5 批次重跑 | 历史、幂等重跑、陈旧拒绝 | `GET /api/batches`、`POST /api/batches/{id}/rerun` |
| M6 调整单导出 | 调整单与清单下载 | `GET /api/export`、`GET /api/export/download` |
| M7 复核台账 | 重复组、红字冲减、供应商汇总、守恒检查 | `GET /api/audit`、`GET /api/audit/dups`、`GET /api/audit/vendors` |

## 核心规则

1. 匹配键 `(采购单号, 行号)` 全程按字符串保形，`01` 不等于 `1`。
2. 价税合计 = 不含税金额 × (1 + 税率)，Decimal 量化 0.01；金额容差 0.02 元，数量容差 0。
3. 差异优先级固定：缺单 > 税额差 > 价差 > 量差；一行命中多类时取最高优先，`reasons` 保留全部。
4. 调整单：差异总额按采购单的发票不含税金额加权，最大余额法分摊，合计严格等于差异总额。
5. 批次键 = `sha256(输入摘要 + 评估日)`；同键同版本复用，同键更新版本建新批次，同键更旧版本 409。
6. 供应商净额 = 发票价税合计 + 已冲抵红字；未冲抵红字挂待确认，不静默冲减。
7. 红字金额必须为负，`(250.00)`、`－76.00`、`-0.678万元` 先归符号与单位再用。
8. 分批入库实收 = 各批相加，未入库 = 订单数量 − 实收；发票税率与采购单不同按发票税率重算应付。

规则细节见 `docs/DEPTH.md`，字段与精度见 `docs/DATA-DICTIONARY.md`，接口见 `docs/API.md`。

## 启动

```bash
docker compose up -d --build
# 打开 http://127.0.0.1:18203/
curl -s -X POST http://127.0.0.1:18203/api/import -H 'Content-Type: application/json' -d '{}'
curl -s http://127.0.0.1:18203/api/reconcile
```

本地直接跑：

```bash
pip install -r requirements.txt
uvicorn app.main:create_app --factory --host 127.0.0.1 --port 18203
pytest -q
```

重建数据库：`docker compose down -v` 后重新 `up`（SQLite 落在命名卷 `invoice3way-data`）。

## 演示步骤

1. 打开 `/`，勾选默认的三份脏样例，点「导入」。
2. 看阶段诊断：采信 48 行、金额 41 行、质量 41 行、匹配 16 键、对账四账平、调整单 3 行。
3. 打开 `/matches`：左右分栏看三单对照，差异行左侧有琥珀色标记列。
4. 打开 `/diffs`：价差 30.00、量差 2、税额差 6.69，各有证据行号。
5. 打开 `/adjust`：调整单三行（175.80 / 16.04 / 49.44），尾差 0.00。
6. 打开 `/batches`：点「重跑」，返回同一个批次号；带旧版本重跑返回 409。
7. 打开 `/export`：四账、下载调整单 CSV 与运行清单 JSON。
8. 打开 `/audit`：供应商汇总 10 家（净额 303299.91）、红字 7 行（已冲抵 -98913.34）、
   分批入库逐批明细、四条守恒检查全平。

## 已知不覆盖

见 `docs/DEPTH.md` 末节：发票表内负数行仍整行隔离、跨采购单拆票、同号同额去重的数量裁定均未做；
分批入库与税率变更在样例里无实例，只由构造行测试覆盖。
